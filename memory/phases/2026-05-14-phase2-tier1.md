# Phase 2 retrospective: tier-1 transformer upgrades

**Phase dates:** 2026-05-04 to 2026-05-14
**Commit range:** `0c147b6..fb86c14` for implementation and closeout decisions, with generation-2 baseline artifacts produced afterward

## Goal recap

Phase 2 tested the low-complexity, high-prior transformer improvements from the SOTA roadmap without sacrificing the readability of the pedagogical core model. Each training-affecting change was exposed through a config flag, measured on B1 TinyStories, B2 Chess, and B3 Chemistry at the standard 5000-step contract, and recorded in `memory/experiments/` before a default decision.

The phase intentionally avoided a broad rewrite. `scratchgpt/model/model.py` remains the educational reference path. Modernization pressure that would obscure that file is now explicitly redirected toward a future parallel `model_modern.py`.

## What shipped

Phase 2 added five architecture flags to `ScratchGPTArchitecture` and wired them through the model:

- `attention_scale_mode`: `"head"` is now default; `"embedding"` preserves the Phase 1 bug for reproduction.
- `ffn_activation`: `"gelu"` is now default; `"relu"` remains available.
- `tie_weights`: remains available but defaults to `false`.
- `init_scheme`: `"gpt2"` is now default; `"default"` preserves PyTorch initialization.
- `use_bias`: remains available and defaults to `true`.

The phase also added `--arch-override KEY=VALUE` to the benchmark scripts, allowing experiments to run from the CLI without editing config files. The model construction path was refactored toward small registries/factories so flag resolution lives in `config.py` and the model file avoids a growing pile of flag-switching branches.

Task 10 added sampling controls to `TransformerLanguageModel.generate()`: `top_k`, `top_p`, and `repetition_penalty`. Decoding policy now lives in `scratchgpt/model/sampling.py`, keeping the generate loop compact. This did not require benchmark runs because default generation behavior is unchanged.

Finally, the roadmap was updated after Phase 2 to prioritize model-first architecture research, benchmark refresh, and paper-grade experiment tracking before hardware-oriented trainer work. See `memory/decisions/2026-05-14-model-first-roadmap.md`.

## What we learned

The attention-scale bug fix was a small but clean win. Switching from `1/sqrt(embedding_size)` to `1/sqrt(head_size)` improved B1 and B3, left B2 flat, and cost no throughput or memory.

GELU was worth shipping. It produced strong B1 and B3 gains with a small throughput cost and a measurable VRAM cost. The B3 result corrected an earlier intuition: floor-bounded structured benchmarks can amplify real relative improvements, while noise-dominated structured benchmarks may stay flat.

Standalone weight tying was a major failure under PyTorch default initialization. The issue was not weight sharing itself; it was an initialization-scale mismatch between `nn.Embedding` and `nn.Linear`. This corrected the earlier B1 throughput finding: B1's output head bottleneck is dominated by output matmul, logits activation memory, and softmax work, not merely by parameter count.

GPT-2 initialization was the phase's largest quality win. It improved all three benchmarks substantially and showed that short 5000-step budgets amplify initialization quality because the baseline has little time to recover from poor initial scales.

Removing biases was not worth shipping. The regression was small but consistent across all three benchmarks, with no compensating readability or speed advantage under the standard contract.

The full Phase 2 stack rescued weight tying from the catastrophic Exp-3 failure, but it was not a clean default flip. It changed both `tie_weights` and `use_bias` relative to accepted defaults, improved B1/B2 marginally, and slightly regressed B3. The clean `tie_weights=true` + `init_scheme=gpt2` ablation is explicitly deferred and is not a blocker for Phase 2 closeout.

## What's different in the next phase because of this

Phase 3 is no longer primarily a trainer-throughput phase. The current roadmap prioritizes model-quality research: refresh the benchmark suite, then build and measure a modern dense decoder path with RoPE or p-RoPE, RMSNorm, parameter-matched SwiGLU, QK-norm, and stack ablations. Trainer work such as mixed precision, `torch.compile`, and KV cache moves into support status unless it is needed for scientific validity or tractable experiment runtime.

Generation-2 canonical baselines are now committed under `runs/baseline-p2-*`. They use the accepted Phase 2 defaults listed above and do not include the deferred tie+GPT-2-init ablation.

## Outstanding debt

The Phase 2 mid-phase handoff note remains in `memory/phases/2026-05-05-phase2-progress.md` as historical context, but this retrospective supersedes it for current state.

The B1 throughput finding has already been corrected in place, but future write-ups should emphasize the revised mechanism: output-head compute and activation memory dominate, not just parameter count.

The new model-first roadmap needs concrete phase plans before implementation starts. The first such plan should scope the benchmark refresh and specify generation labels so old Phase 1/2 results are not compared casually against refreshed datasets.
